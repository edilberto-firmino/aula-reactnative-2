01 · O que vamos construir nesta aula

Na primeira prática, você preparou o ambiente e abriu uma tela simples. Agora vai transformar essa base em uma tela de apresentação de um evento fictício, usando React Native, Expo e JavaScript.

Ao final, você deverá identificar componentes, organizar estilos, exibir uma imagem local, passar dados por propriedades e responder ao toque em um botão. A prática pode ser individual ou em dupla.

Conheça o encontro e experimente a interação.

OFICINA • TECNOLOGIA

Encontro de Tecnologia

Data: 21 de outubro de 2026, às 19h

Local: Auditório do campus

Uma conversa sobre aplicativos, criatividade e soluções para o dia a dia.

Evento fictício para fins didáticos.

A representação acima é uma prévia HTML do resultado, não o aplicativo React Native. Toque no botão para conhecer a mensagem de simulação. A aparência do alerta real depende da plataforma.

Escopo: uma tela, um cartão e uma interação. Não há inscrição real, envio de dados, login, banco de dados ou navegação nesta prática.

03 · Instalar e conferir as ferramentas

  1. Instale Node.js LTS, incluindo npm e a opção de PATH do instalador.
  2. Instale Visual Studio Code.
  3. No celular, instale Expo Go conforme expo.dev/go.
  4. Feche e reabra o terminal após instalar Node.js. No VS Code, use Terminal → Novo Terminal.
Terminal — verificação
node --version
npm --version
O que você deve ver: duas versões, uma do Node.js e outra do npm. Os números podem ser diferentes dos apresentados pelo professor.

O projeto encontrado na primeira prática usa Expo SDK 57. A tabela oficial desse SDK informa Node.js mínimo 22.13.x. Se criar outro SDK, confira o requisito correspondente. Não altere as versões do projeto apenas para reproduzir um número deste manual.

Quem já possui ferramentas funcionando pode apenas conferir as versões. Não é necessário instalar a antiga CLI global expo-cli. Android Studio é opcional quando você usa celular com Expo Go. O computador e o celular precisam conseguir se comunicar pela rede.

04 · Escolher: continuar ou criar um projeto

Caminho A — Continuar a primeira prática

Faça uma cópia de segurança de App.js e de outros arquivos que pretende substituir, fora da pasta do projeto. Abra minhas-tarefas-expo no VS Code. No terminal da pasta INBEC:

Terminal — projeto existente
cd minhas-tarefas-expo
npm install

npm install recupera dependências a partir do projeto; é útil quando elas ainda não estão instaladas. Se você já está dentro da pasta do aplicativo, não execute o cd novamente.

Caminho B — Começar um projeto separado

No terminal de sua pasta de trabalho, execute:

Terminal — novo projeto
npx create-expo-app@latest eventos-campus --template blank
cd eventos-campus

Se o npm solicitar autorização para baixar o gerador, responda y e aguarde o término. Abra a pasta eventos-campus no VS Code por Arquivo → Abrir Pasta.

O que você deve ver: arquivos como App.js, index.js, app.json e package.json, além da pasta assets. O nome da pasta depende do caminho escolhido.
Escolha somente um caminho. Esta prática utiliza o template blank em JavaScript, com App.js. Se seu projeto tem src/app, arquivos .tsx ou Expo Router, peça orientação antes de copiar: a entrada é diferente. A pasta do manual aula-pratica-2 não é a raiz de um aplicativo Expo.

07 · Código completo de App.js

Substitua o conteúdo de App.js pelo código abaixo. O objeto evento concentra as informações fictícias; mostrarInteresse é a função acionada pelo cartão.

App.js
Baixar arquivo
import { Alert, Platform, ScrollView, Text, View } from 'react-native';
import { StatusBar } from 'expo-status-bar';
import { SafeAreaProvider, SafeAreaView } from 'react-native-safe-area-context';
import CartaoEvento from './components/CartaoEvento';
import styles from './styles';

const evento = {
  nome: 'Encontro de Tecnologia',
  data: '21 de outubro de 2026, às 19h',
  local: 'Auditório do campus',
  descricao: 'Uma conversa sobre aplicativos, criatividade e soluções para o dia a dia.',
  imagem: require('./assets/evento.png'),
};

export default function App() {
  function mostrarInteresse() {
    const mensagem = `Você demonstrou interesse em ${evento.nome}. Esta é uma simulação: nenhuma inscrição foi enviada.`;
    if (Platform.OS === 'web') {
      globalThis.alert(mensagem);
      return;
    }
    Alert.alert('Interesse demonstrado', mensagem, [{ text: 'Entendi' }]);
  }

  return (
    <SafeAreaProvider>
      <SafeAreaView style={styles.safe}>
        <StatusBar style="dark" />
        <ScrollView contentContainerStyle={styles.pagina}>
          <View style={styles.conteudo}>
            <Text style={styles.etiqueta}>EVENTOS DO CAMPUS</Text>
            <Text style={styles.titulo}>Vamos aprender juntos?</Text>
            <Text style={styles.introducao}>Conheça o encontro e toque no botão para experimentar a interação.</Text>
            <CartaoEvento evento={evento} onInteresse={mostrarInteresse} />
            <Text style={styles.rodape}>Atividade prática 2 • Professor Edilberto Firmino</Text>
            <Text style={styles.aviso}>Evento fictício para fins didáticos.</Text>
          </View>
        </ScrollView>
      </SafeAreaView>
    </SafeAreaProvider>
  );
}

08 · Código completo de components/CartaoEvento.js

Crie este arquivo dentro de components. Ele recebe evento e onInteresse por props. O botão usa a função recebida, e os textos usam os dados do evento.

components/CartaoEvento.js
Baixar arquivo
import { Image, Pressable, Text, View } from 'react-native';
import styles from '../styles';

export default function CartaoEvento({ evento, onInteresse }) {
  return (
    <View style={styles.cartao}>
      <Image
        source={evento.imagem}
        style={styles.imagem}
        resizeMode="cover"
        accessibilityLabel="Ilustração de um encontro de tecnologia"
      />
      <View style={styles.detalhes}>
        <Text style={styles.categoria}>OFICINA • TECNOLOGIA</Text>
        <Text style={styles.nome}>{evento.nome}</Text>
        <Text style={styles.informacao}>Data: {evento.data}</Text>
        <Text style={styles.informacao}>Local: {evento.local}</Text>
        <Text style={styles.descricao}>{evento.descricao}</Text>
        <Pressable
          onPress={onInteresse}
          accessibilityRole="button"
          accessibilityLabel={`Demonstrar interesse em ${evento.nome}`}
          style={({ pressed }) => [styles.botao, pressed && styles.botaoPressionado]}
        >
          <Text style={styles.textoBotao}>Tenho interesse</Text>
        </Pressable>
      </View>
    </View>
  );
}

10 · Entender o código que você acabou de criar

ConceitoOnde apareceO que significa
JSXBlocos dentro de returnDescreve a árvore da interface no JavaScript.
ViewConteúdo e cartãoAgrupa elementos e organiza o layout.
TextTítulos e informaçõesExibe conteúdo textual; não deixe texto solto em View.
ImageTopo do cartãoExibe a imagem indicada em source.
PressableTenho interesseResponde ao toque e informa se está pressionado.
ScrollViewTela principalPermite alcançar conteúdo maior que a altura disponível.
Propsevento e onInteresseDados e função enviados de App para CartaoEvento.
StyleSheet.createstyles.jsOrganiza estilos em objetos JavaScript.
SafeAreaProvider / SafeAreaViewRaiz da telaFornecem contexto e espaçamento para áreas seguras.
Platform e AlertmostrarInteresseSelecionam a mensagem adequada ao ambiente de execução.

O caminho de um toque

Você toca no Pressable → ele chama onInteresse → essa prop aponta para mostrarInteresse → a função monta a mensagem com evento.nome → o sistema mostra um alerta.

Comparação — função e execução
// Correto: entrega a função para ser chamada no toque.
onPress={onInteresse}

// Evite: chama a função enquanto o componente é renderizado.
onPress={onInteresse()}

Dados e caminhos

As chaves em {evento.nome} inserem um valor JavaScript no JSX. O require('./assets/evento.png') usa um caminho literal relativo ao App.js. No cartão, ../styles sobe uma pasta até a raiz.

Estilos que serão observados

padding cria espaço interno; marginBottom separa um elemento do próximo; gap separa os filhos do contêiner. flex: 1 faz a área principal ocupar o espaço disponível. maxWidth limita a largura de leitura, e alignSelf: 'center' centraliza o conteúdo em telas largas.

A imagem usa largura de 100% e proporção 2:1. O cartão não tem altura fixa, permitindo que textos cresçam. A opacidade do botão muda durante o toque; isso não registra interesse nem altera um estado persistente.

12 · Alternativas: navegador, emulador e túnel

Navegador

Na raiz do aplicativo, instale o suporte web e inicie:

Terminal — web opcional
npx expo install react-dom react-native-web @expo/metro-runtime
npx expo start --web

Use o endereço mostrado no terminal. Reduza e aumente a janela para observar o cartão. O exemplo inclui uma mensagem para web, mas áreas seguras e comportamento de toque precisam ser conferidos no aparelho.

Emulador Android

  1. Instale Android Studio e conclua a configuração do SDK.
  2. No Device Manager, crie um aparelho virtual, baixe a imagem de sistema e inicie-o.
  3. Com Metro em execução, pressione a para abrir no Android. Aguarde a inicialização e siga as mensagens do Expo.

Prepare o emulador antes da aula: o download e a primeira inicialização podem demorar. Consulte o guia oficial de configuração Android. Simulador iOS exige macOS e Xcode.

Rede local bloqueada

Se a rede impedir a comunicação, pare Metro com Ctrl+C e tente:

Terminal — túnel
npx expo start --go --tunnel

O túnel exige internet, pode solicitar instalação de uma dependência e pode ser mais lento. Escaneie o novo QR code. Se não funcionar, registre o erro e use a alternativa disponível com o professor.

13 · Experimentos guiados durante a aula

Faça uma mudança por vez, preveja o resultado e confira depois de salvar.

  1. Texto: altere evento.nome, data, local e descricao no App.js. Observe que o componente continua sendo o mesmo.
  2. Cor: em styles.js, mude backgroundColor do botão para '#166534'. Preserve texto legível.
  3. Espaçamento: compare padding 12, 20 e 28 em detalhes. Explique o que mudou.
  4. Imagem: copie outro PNG ou JPG para assets, ajuste o require literal e a descrição acessível. Prefira uma imagem de proporção semelhante.
  5. Texto longo: use um nome de evento maior e uma descrição com várias linhas. Confira quebra de linha e rolagem.
  6. Botão: mude o rótulo e a mensagem de forma coerente, mantendo explícita a simulação.
Desafio opcional: exibir dois cartões

Crie outro objeto de evento no App.js, com nome, data, local, descricao e imagem. Renderize outro CartaoEvento passando esse objeto. Para que a mensagem use o nome correto, faça mostrarInteresse receber o evento selecionado e passe uma função como onInteresse={() => mostrarInteresse(outroEvento)}. Ajuste também o primeiro cartão para passar seu evento. Use uma View com gap para separar os cartões.

15 · Atividade: seu evento no campus

Situação: sua equipe precisa apresentar uma oficina, palestra ou encontro fictício em uma tela para celular.

  1. Escolha um evento e personalize nome, data, local e descrição.
  2. Troque a imagem por outra adequada ao tema, mantendo-a local.
  3. Personalize a cor do botão e o título da página.
  4. Inclua os nomes dos integrantes no rodapé.
  5. Mantenha a mensagem do botão vinculada ao nome do evento e o aviso de simulação.
  6. Teste a tela e explique a função de cada arquivo.

Perguntas para responder

  1. Qual a diferença entre o index.html deste manual e o App.js do aplicativo?
  2. Para que servem View, Text, Image e Pressable?
  3. Quais props App envia para CartaoEvento?
  4. Por que onPress recebe uma função?
  5. Qual a diferença observada entre padding e margin?
  6. Por que o alerta não representa uma inscrição salva?
  7. Qual teste foi realizado no aparelho e qual ainda está pendente?

Entrega

Envie App.js, styles.js, components/CartaoEvento.js, a imagem utilizada, package.json e package-lock.json; duas capturas (tela e mensagem do botão); as respostas e um registro de dificuldade ou verificação realizada. Identifique se as capturas vieram de celular, emulador ou navegador. Não é necessário enviar node_modules.

O professor define o prazo e a pontuação. Se não houver aparelho disponível, registre a execução web e deixe o teste nativo identificado como pendente.
